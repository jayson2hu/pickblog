L3 应用与分发 — 详尽开发计划

L3 是面向终端的产品集：Reader Web、Public API/MCP、Brief。消费 L2 的 COMPLETED 判断，做体验、分发、商业化。拆成 10 EPIC / ~32 小功能；前端 Next.js + 后端 FastAPI。可对 L2 stub 独立开发。

范围：Reader+API+MCP+Brief+计费 EPIC：10小功能：~32 预估：~20 人日 栈：Next.js · FastAPI · PG · Paddle/Stripe

i说明与范围

仅覆盖 L3。消费 L2 的 COMPLETED 内容 + 评分 + 翻译，产出用户产品。MUST=MVP，SHOULD=V1，V2=后置。

⇄并行开发与契约

⬇ 输入契约（来自 L2，可 stub）

  • 只读 COMPLETED 内容 + content_vertical_scores + content_translations
  • 请求时调 L2 recommend() / companion()
  • standalone：StubContentReadProvider + fixtures

⬆ 输出（终端）

  • Reader Web 页面 · 早报邮件
  • Public API /v1 + MCP 工具
  • 北极星埋点：深度阅读闭环率
统一接缝：L3 拥有 users/subscriptions/interests/follows/reading_events/briefs/bookmarks/api_keys/api_usage_daily/companion_usage 表，只读 L0–L2 内容/评分/翻译。集成时换 ContentReadProvider 为真 L2 + 接平台事件即可。

▤数据库 DDL（L3 拥有）

CREATE TABLE users(id BIGSERIAL PK, email UNIQUE, nickname, locale, plan DEFAULT 'free', created_at);
CREATE TABLE subscriptions(user_id, plan, status, period_end, provider, provider_ref);
CREATE TABLE user_interests(user_id, tag_code, weight, PK(user_id,tag_code));
CREATE TABLE user_follows(user_id, target_type, target_id);
CREATE TABLE reading_events(id BIGSERIAL PK, user_id, content_id, type, ts);
CREATE TABLE briefs(id BIGSERIAL PK, user_id NULL, vertical_code, brief_date, items JSONB, channels JSONB, status);
CREATE TABLE bookmarks(user_id, content_id, note, highlights JSONB, PK(user_id,content_id));
CREATE TABLE api_keys(id BIGSERIAL PK, owner_user_id, key_hash UNIQUE, prefix, scopes TEXT[], rate_limit_rpm, daily_quota, status);
CREATE TABLE api_usage_daily(key_id, day, count, PK(key_id,day));
CREATE TABLE companion_usage(user_id, day, count, PK(user_id,day));
